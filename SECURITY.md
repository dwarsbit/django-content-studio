# Security policy

## Supported versions

Security fixes land in the latest release. Before 1.0, only the most recent
release candidate is supported; from 1.0, the latest 1.x release is.

## Reporting a vulnerability

Please do **not** open a public issue for a security problem. Report it
privately instead:

- through GitHub's [private vulnerability reporting](https://github.com/dwarsbit/django-content-studio/security/advisories/new), or
- by email to leon@dwarsbit.nl.

Include what you found, the affected version, and the steps or a proof of
concept to reproduce it. You can expect an acknowledgement within a few
working days; we will keep you informed while we work on a fix and credit
you in the changelog unless you prefer otherwise.

## Deploying securely

The [Security](https://djangocontentstudio.org/docs/security)
page of the documentation describes how Content Studio protects its
interface and the checklist for running it in production.
