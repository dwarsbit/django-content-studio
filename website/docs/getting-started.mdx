# 🚀 Getting started

## Install the package

```bash
pip install django-content-studio
```

## Configure Django

Add Content Studio and Django REST Framework to `INSTALLED_APPS`. Content
Studio builds its API from models registered with the Django admin, so
`django.contrib.admin` must come **before** `content_studio`:

```python
# settings.py
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "rest_framework",
    "content_studio",
    # ... your apps
]
```

Mount the interface at any prefix — `admin/` is the conventional choice:

```python
# urls.py
from django.urls import include, path

urlpatterns = [
    path("admin/", include("content_studio.urls")),
    # ... your urls
]
```

The interface (and everything it needs) is served under this prefix — no
further URL configuration required.

## Initialize Content Studio

The `init_content_studio` command sets up the pieces above and beyond:

```bash
python manage.py init_content_studio
```

It asks which model to use for the media library (item and folder — none
by default), whether to use a tenant model, and which login backend to
enable (today: `UsernamePasswordBackend`). The prompts are arrow-key
selections; **ESC** asks for confirmation to abort the command. It then:

- creates a `studio.py` next to your settings with a `ContentStudioSite`
  instance, with the customization hooks commented in;
- adds the `CONTENT_STUDIO` block to your settings, pointing
  `ADMIN_SITE` at the new site — reported and skipped when a
  `CONTENT_STUDIO` block already exists, so nothing you configured by
  hand gets rewritten.

Every choice can also be passed as a flag, so the command runs unattended:
`--media-item`, `--media-folder`, `--tenant` (each as `app_label.Model`)
and `--login-backend`, plus `--no-input` to accept the defaults for
everything unset. The command validates its choices through
[System checks](/docs/system-checks) — run `manage.py check` afterwards.

## Register a model

```python
# apps/blog/admin.py
from django.db import models
from content_studio import register
from content_studio.admin import ModelStudio


class Article(models.Model):
    class Status(models.TextChoices):
        DRAFT = "draft", "Draft"
        PUBLISHED = "published", "Published"

    title = models.CharField(max_length=200)
    body = models.TextField(blank=True)
    status = models.CharField(
        max_length=20, choices=Status.choices, default=Status.DRAFT
    )

    def __str__(self):
        return self.title


@register(Article)
class ArticleStudio(ModelStudio):
    table_display = ["title", "status"]
    list_filter = ["status"]
    search_fields = ["title"]
```

That's it. 🎉 Start the development server and open `/admin/`: the article
appears in the menu, with a list view (searchable, filterable) and an edit
view rendered from the model's fields.

## Log in

Content Studio authenticates through JSON Web Tokens. By default the
`UsernamePasswordBackend` is enabled: log in with the username and password of
any staff user, exactly like the Django admin. Custom login backends and
throttling are covered under [authentication](/docs/authentication).
