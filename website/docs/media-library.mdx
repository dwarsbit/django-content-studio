# 🖼️ Media library

The media library is where editors upload and organize files: images,
video, audio and documents, in folders. Fields such as `MediaField` then
pick files from it. The library works with your own media models, or with
the ready-made models Content Studio ships.

## Set it up with your own models

Point the settings at a media item model and, optionally, a folder model:

```python
# mysite/settings.py
CONTENT_STUDIO = {
    "MEDIA_LIBRARY_MODEL": "blog.models.MediaItem",
    "MEDIA_LIBRARY_FOLDER_MODEL": "blog.models.MediaFolder",
}
```

A media item model needs these fields:

- `file`: the upload, a `FileField` or `ImageField`.
- `name`: shown on the item and used by the search.
- `type`: one of `"image"`, `"video"`, `"audio"` or `"file"`; it decides
  the preview.
- `tags` (optional): a list of strings, such as a `JSONField`, an
  `ArrayField` or the built-in `TagField`. Searched together with the name.
- `alt_text` (optional): a short text alternative for the file.
- `metadata` (optional): a `JSONField` for the [metadata](#metadata) read
  from the file.
- `properties` (optional): a `JSONField` for the [properties](#properties)
  editors set, such as an image's focal point.

The fields above apply to every type of media. A value that applies to only some
types of media, such as an image's focal point, belongs in `metadata` when
it is read from the file, and in `properties` when editors set it.

A folder model needs a `name` and a `parent` foreign key to itself. System
check `content_studio.W007` reports missing fields. Without the
`MEDIA_LIBRARY_MODEL` setting, the media library does not appear in the
admin.

## Or use the built-in models

The `content_studio.media_library` app ships media item and folder models
that follow these rules, with migrations. Add the app and point the
settings at its models:

```python
# mysite/settings.py
INSTALLED_APPS = [
    # ...
    "content_studio",
    "content_studio.media_library",
]

CONTENT_STUDIO = {
    "MEDIA_LIBRARY_MODEL": "content_studio.media_library.models.Media",
    "MEDIA_LIBRARY_FOLDER_MODEL": "content_studio.media_library.models.Folder",
}
```

With [multi-tenancy](/docs/multi-tenancy), the media library is shared by
every tenant.

Deleting an item also removes its file from storage, and replacing an item's
file removes the previous one. With your own models, a replaced file is
removed as well; a deleted item's file stays unless your model removes it,
for example in a `post_delete` receiver.

## Working in the media library

Editors upload files with the upload button or by dragging them onto the
library, and add tags in the same step when the model has a `tags` field.
They move files between folders, edit their details, and copy or download a
file from its menu.

The library has three views: a **grid** of thumbnails, a **list** and a
**table** with sortable columns for name, type and size. The admin remembers
the view, the filters and the sort order per media model. The search and the
current folder are part of the URL, so a filtered view survives a reload and
the back button.

The search matches names and tags. Two filters narrow the items further:

- **Type**: image, video, audio or file.
- **Tags**: any of the selected tags.

With folders, the search covers the current folder or the whole library, set
with the toggle next to the search box. Each folder shows how many items it
holds.

Browsing the media library, also from a media field, needs the media
model's view or change permission; that permission also opens the folders.
Select items to delete them or move them to another folder. Deleting needs
the model's delete permission, moving its change permission.

## Uploads

The media library accepts the file types in
[`MEDIA_LIBRARY_ALLOWED_EXTENSIONS`](/docs/settings#media_library_allowed_extensions),
up to [`MEDIA_LIBRARY_MAX_UPLOAD_SIZE`](/docs/settings#media_library_max_upload_size)
(50 MB by default). It rejects files whose content is markup, such as HTML or
SVG: served from your own domain, such a file could run scripts in your
editors' sessions.

## Thumbnails

The admin shows images in two sizes: small thumbnails in the media library,
pickers and list pages, and large ones in the cover image widget, cropping
and the focal point. With the `images` extra installed, Content Studio makes
both from the uploaded image:

```bash
pip install "django-content-studio[images]"
```

Thumbnails are saved in the image's own storage, in the folder set by
[`THUMBNAIL_FOLDER`](/docs/settings#thumbnail_folder). Content Studio makes
them when an image is uploaded, replaced or cropped, and the first time an
image you already have is shown. It removes them with the image.

Making a thumbnail takes a moment, so a library of existing images is slow
the first time the admin shows it. Make the missing thumbnails in advance:

```bash
python manage.py content_studio_thumbnails
```

Pass `--all` to make every thumbnail again.

With several worker processes or servers, configure a shared cache for
[`THUMBNAIL_CACHE`](/docs/settings#thumbnail_cache), such as Redis,
Memcached or the database cache.

Without Pillow, with `THUMBNAIL_FOLDER` set to `None`, or for a file it
cannot read, the admin shows the image file itself. To serve thumbnails
another way, override [`get_thumbnail`](#customize-with-site-hooks).

## Image sizes

Thumbnails are for the admin. For your site, apps and other consumers, name
the sizes you need in [`IMAGE_SIZES`](/docs/settings#image_sizes), and
Content Studio makes every image in each of them:

```python
CONTENT_STUDIO = {
    # ...
    "IMAGE_SIZES": {
        "card": {"width": 600, "height": 400, "fit": "cover"},
        "hero": {"width": 1920},
        "share": {"width": 1200, "height": 630, "fit": "cover", "format": "jpeg"},
    },
}
```

Each size takes these options:

| Option | Default | Meaning |
|--------|---------|---------|
| `width`, `height` | | The box in pixels. Give one or both; a side left out is free. |
| `fit` | `"contain"` | `"contain"` scales the image to fit inside the box. `"cover"` fills the box exactly, cut around the [focal point](#focal-points); it needs both sides. |
| `format` | `"webp"` | `"webp"`, `"jpeg"`, `"png"`, or `"original"` to keep the uploaded format (WebP for other formats). |
| `quality` | `82` | The quality of WebP and JPEG images, from 1 to 100. |
| `upscale` | `False` | Whether a smaller image is enlarged to the size. Without it, a small image gives a smaller size of the same shape. |

Sizes need the `images` extra and a media model with a metadata field (the
built-in `Media` model has one). Content Studio makes them after an image is
uploaded, replaced, cropped or reset, and makes the `"cover"` sizes again
when its focal point moves. They are saved in the image's own storage, in
the folder set by [`IMAGE_SIZE_FOLDER`](/docs/settings#image_size_folder)
(`"content_studio/sizes"` by default), and recorded in the item's metadata.
A size's file name changes whenever its image, its options or its focal
point change, so you can cache the files for as long as you like. Sizes that
are replaced, and the sizes of a deleted image, are removed.

### Use the sizes

`get_image_sizes` returns every size of an image, with its URL and the width
and height it has:

```python
from content_studio.media_library.sizes import get_image_sizes

get_image_sizes(article.cover)
# {"card": {"url": "/media/content_studio/sizes/...-card-....webp",
#           "width": 600, "height": 400, "ready": True},
#  "hero": {...}, "share": {...}}
```

In templates, use the `image_url` and `image_size` tags of the
`content_studio` library:

```django
{% load content_studio %}

<img src="{% image_url article.cover "hero" %}" alt="{{ article.cover.alt_text }}">

{% image_size article.cover "card" as card %}
<img src="{{ card.url }}" width="{{ card.width }}" height="{{ card.height }}" alt="">
```

A size that is not made yet is the image's own file, with `ready` set to
`False`: an image is never missing, only larger for a moment. An item that is
not an image has no sizes (`{}`), and an unknown size name gives `None` in
`image_size` and an empty string in `image_url`.

### Making sizes in the background

Content Studio makes the sizes in a [Django task](https://docs.djangoproject.com/en/stable/topics/tasks/).
Without a `TASKS` setting, Django runs it right after the change is saved,
in the same request. To keep uploads and crops fast, configure a task
backend that runs it in a worker, such as [Huey](/docs/dashboard#huey).
On Django 5.2, install the `django-tasks` backport to use a backend;
without it, the sizes are made in the request.

After you add or change a size, existing images are out of date: they show
their own file until their sizes are made. Make them, and remove the sizes
you no longer configure, with:

```bash
python manage.py content_studio_image_sizes
```

Pass `--all` to make every size again.

## Cropping and focal points

A crop removes what must never be shown, such as a watermark or a bystander;
the focal point decides which part of an image stays in view where your site
shows it smaller or in another shape.

### Cropping

Images can be cropped once Content Studio can read them: install the
`images` extra, and give your media model a [metadata](#metadata) field (the
built-in `Media` model has one):

```bash
pip install "django-content-studio[images]"
```

Editors crop an image from its details. A crop is cut from the image at full
size and is never resized. The crop becomes the item's file, so
`{{ item.file.url }}` and everything else that shows the file shows the crop.
The original is kept: cropping again starts from the original, and
**Reset to original** puts it back. An image has one original and one crop.

The item's metadata names the original and the crop, as percentages of the
original:

```python
{
    "width": 1200,
    "height": 800,
    "crop": {
        "original": "3f1c0b8e-…",
        "width": 4000,
        "height": 3000,
        "box": {"x": 10.0, "y": 20.0, "width": 30.0, "height": 26.67},
    },
}
```

`width` and `height` are the crop's size; `crop` holds the original's
storage name and size. Replacing an item's file removes its crop and its
original, and so does deleting the item. Animated images cannot be cropped.

To crop another way, override `crop_image` on your site. It receives the
item and the editor's selection, as percentages of the image:

```python
# mysite/studio.py
from content_studio.admin import ContentStudioSite


class BlogStudioSite(ContentStudioSite):
    def crop_image(self, obj, crop_info):
        # {"x": "10.00", "y": "20.00", "width": "50.00", "height": "40.00", "unit": "%"}
        # Store the selection, for a template tag of your own to apply.
        obj.properties = {**obj.properties, "crop": crop_info}
        obj.save(update_fields=["properties"])


admin_site = BlogStudioSite()
```

Your method decides what a crop does: create a derivative, change the file
or store the selection. Your site's method also turns cropping on without
Pillow or a metadata field. Override `reset_crop(obj)` as well to offer
**Reset to original** for your own crops.

### Focal points

A focal point is one of the image's [properties](#properties): editors click
the image to set it. The [cover image widget](/docs/widgets#cover-images)
sets the same focal point from the edit page. The focal point is relative to
the image as it is shown, so the built-in crop and reset move it along; a
focal point outside a new crop moves to the crop's nearest edge.

## Metadata

The media library can store facts about each file, read once when the file
is uploaded or replaced: an image's width and height, or a video's duration.
The admin shows them in the file's details, and the
[cover image widget](/docs/widgets#cover-images) uses an image's size
to warn about images that are too small.

1. Give your media item model a `JSONField` named `metadata`. The built-in
   `Media` model has one. To use a field by another name, name it in
   [`MEDIA_METADATA_ATTR`](/docs/settings#media_metadata_attr):

   ```python
   # blog/models.py
   from django.db import models


   class MediaItem(models.Model):
       class Type(models.TextChoices):
           IMAGE = "image", "Image"
           VIDEO = "video", "Video"
           AUDIO = "audio", "Audio"
           FILE = "file", "File"

       file = models.FileField(upload_to="media/")
       name = models.CharField(max_length=255, blank=True)
       type = models.CharField(max_length=10, choices=Type.choices, default=Type.FILE)
       metadata = models.JSONField(default=dict, blank=True, editable=False)

       def __str__(self):
           return self.name
   ```

2. Install Content Studio with the `images` extra, which adds
   [Pillow](https://python-pillow.org/) to read the size of images:

   ```bash
   pip install "django-content-studio[images]"
   ```

3. Read the metadata of the files you already have:

   ```bash
   python manage.py content_studio_media_metadata
   ```

   The command reads the items without metadata. Pass `--all` to read every
   item again, for example after you change what is read.

Images get `{"width": 1600, "height": 900}`, in pixels as the image is shown,
after its EXIF orientation. Other files get no metadata by default: a video's
duration and frame rate need a tool such as
[FFmpeg](https://ffmpeg.org/)'s `ffprobe`. Override `get_media_metadata` on
your site to read them. It receives the uploaded file and the item's type
(`"image"`, `"video"`, `"audio"` or `"file"`) and returns a dictionary of
JSON values:

```python
# mysite/studio.py
import json
import subprocess
import tempfile

from content_studio.admin import ContentStudioSite


class BlogStudioSite(ContentStudioSite):
    def get_media_metadata(self, file, type):
        if type != "video":
            return super().get_media_metadata(file, type)

        # ffprobe reads from a path: copy the upload to a temporary file.
        with tempfile.NamedTemporaryFile() as copy:
            file.seek(0)
            for chunk in file.chunks():
                copy.write(chunk)
            copy.flush()
            file.seek(0)

            result = subprocess.run(
                [
                    "ffprobe",
                    "-v",
                    "error",
                    "-select_streams",
                    "v:0",
                    "-show_entries",
                    "stream=width,height,r_frame_rate:format=duration",
                    "-of",
                    "json",
                    copy.name,
                ],
                capture_output=True,
                check=True,
                text=True,
            )

        probe = json.loads(result.stdout)
        stream = probe["streams"][0]
        frames, seconds = stream["r_frame_rate"].split("/")

        return {
            "width": stream["width"],
            "height": stream["height"],
            "duration": float(probe["format"]["duration"]),
            "frame_rate": round(int(frames) / int(seconds), 2),
        }


admin_site = BlogStudioSite()
```

The admin shows `width` and `height` in pixels, `duration` in seconds as
minutes and seconds, and `frame_rate` in frames per second. Other keys are
stored for your own templates and code. The method runs during the upload
request, so keep it fast; an exception in it fails the upload.

## Properties

Properties are values editors set for some types of media, stored in a
`JSONField` on the media item. The built-in `Media` model has a `properties`
field; give your own media model a `JSONField` named `properties`, or name
another one in [`MEDIA_PROPERTIES_ATTR`](/docs/settings#media_properties_attr):

```python
# blog/models.py
from django.db import models


class MediaItem(models.Model):
    class Type(models.TextChoices):
        IMAGE = "image", "Image"
        VIDEO = "video", "Video"
        AUDIO = "audio", "Audio"
        FILE = "file", "File"

    file = models.FileField(upload_to="media/")
    name = models.CharField(max_length=255, blank=True)
    type = models.CharField(max_length=10, choices=Type.choices, default=Type.FILE)
    properties = models.JSONField(default=dict, blank=True)

    def __str__(self):
        return self.name
```

The admin sets these properties:

- **`focal_point`**: the part of an image that stays in view when it is
  cropped, as `{"x": 0-100, "y": 0-100}`, percentages of the image's width
  and height from its top left. `None` when it is removed.

Unlike [metadata](#metadata), properties are kept when an item's file is
replaced. Other keys are kept as they are, so your own code can store values
there too. Read them in templates like any dictionary:

```django
{# blog/templates/blog/article_detail.html #}
{% with point=article.cover.properties.focal_point %}
  <img
    src="{{ article.cover.file.url }}"
    alt="{{ article.cover.alt_text }}"
    style="object-fit: cover; object-position: {{ point.x|default:50 }}% {{ point.y|default:50 }}%"
  >
{% endwith %}
```

## Customize with site hooks

Five methods on the site change how the media library behaves. Add them to
your site subclass:

```python
# mysite/studio.py
from content_studio.admin import ContentStudioSite


class BlogStudioSite(ContentStudioSite):
    def get_thumbnail(self, obj, size="small"):
        return f"https://images.example.com/{obj.file.name}?size={size}"

    def get_media_serializer_fields(self, media_model):
        return ["id", "name", "type", "tags", "file", "folder"]

    def crop_image(self, obj, crop_info):
        # Crop obj's file the way your project needs.
        ...


admin_site = BlogStudioSite()
```

- **`get_thumbnail(obj, size="small")`** returns the thumbnail URL of an
  image, `"small"` or `"large"`. By default, a [thumbnail](#thumbnails) made
  by Content Studio, or the file's own URL. Override it to serve thumbnails
  from an image service or CDN.
- **`get_media_serializer_fields(media_model)`** returns the fields of a
  media item the admin works with. By default, all fields; leave out fields
  editors should not see.
- **`crop_image(obj, crop_info)`** crops an image. By default, the
  [built-in crop](#cropping-and-focal-points); override it to crop another
  way.
- **`reset_crop(obj)`** undoes a crop. By default, it puts the original back
  that the built-in crop kept.
- **`get_media_metadata(file, type)`** returns the [metadata](#metadata) to
  store for an uploaded file.
