# 🖼️ Media library

The media library is where editors upload and organize files: images,
video, audio and documents, in folders. Fields such as `MediaField` then
pick files from it. The library works with your own media models, or with
the ready-made models Content Studio ships.

## Set it up with your own models

Point the settings at a media item model and, optionally, a folder model:

```python
# mysite/settings.py
CONTENT_STUDIO = {
    "MEDIA_LIBRARY_MODEL": "blog.models.MediaItem",
    "MEDIA_LIBRARY_FOLDER_MODEL": "blog.models.MediaFolder",
}
```

A media item model needs these fields:

- `file`: the upload, a `FileField` or `ImageField`.
- `name`: shown on the item and used by the search.
- `type`: one of `"image"`, `"video"`, `"audio"` or `"file"`; it decides
  the preview.
- `tags` (optional): a list of strings, such as a `JSONField`, an
  `ArrayField` or the built-in `TagField`. Searched together with the name.
- `alt_text` (optional): a short text alternative for the file.
- `metadata` (optional): a `JSONField` for the [metadata](#metadata) read
  from the file.
- `properties` (optional): a `JSONField` for the [properties](#properties)
  editors set, such as an image's focal point.

The fields above apply to every type of media. A value that applies to only some
types of media, such as an image's focal point, belongs in `metadata` when
it is read from the file, and in `properties` when editors set it.

A folder model needs a `name` and a `parent` foreign key to itself. System
check `content_studio.W007` reports missing fields. Without the
`MEDIA_LIBRARY_MODEL` setting, the media library does not appear in the
admin.

## Or use the built-in models

The `content_studio.media_library` app ships media item and folder models
that follow these rules, with migrations. Add the app and point the
settings at its models:

```python
# mysite/settings.py
INSTALLED_APPS = [
    # ...
    "content_studio",
    "content_studio.media_library",
]

CONTENT_STUDIO = {
    "MEDIA_LIBRARY_MODEL": "content_studio.media_library.models.Media",
    "MEDIA_LIBRARY_FOLDER_MODEL": "content_studio.media_library.models.Folder",
}
```

With [multi-tenancy](/docs/multi-tenancy), the media library is shared by
every tenant.

Deleting an item also removes its file from storage, and replacing an item's
file removes the previous one. With your own models, a replaced file is
removed as well; a deleted item's file stays unless your model removes it,
for example in a `post_delete` receiver.

## Working in the media library

Editors upload files with the upload button or by dragging them onto the
library, and add tags in the same step when the model has a `tags` field.
They move files between folders, edit their details, and copy or download a
file from its menu.

The library has three views: a **grid** of thumbnails, a **list** and a
**table** with sortable columns for name, type and size. The admin remembers
the view, the filters and the sort order per media model. The search and the
current folder are part of the URL, so a filtered view survives a reload and
the back button.

The search matches names and tags. Two filters narrow the items further:

- **Type**: image, video, audio or file.
- **Tags**: any of the selected tags.

With folders, the search covers the current folder or the whole library, set
with the toggle next to the search box. Each folder shows how many items it
holds.

Browsing the media library, also from a media field, needs the media
model's view or change permission; that permission also opens the folders.
Select items to delete them or move them to another folder. Deleting needs
the model's delete permission, moving its change permission.

## Uploads

The media library accepts the file types in
[`MEDIA_LIBRARY_ALLOWED_EXTENSIONS`](/docs/settings#media_library_allowed_extensions),
up to [`MEDIA_LIBRARY_MAX_UPLOAD_SIZE`](/docs/settings#media_library_max_upload_size)
(50 MB by default). It rejects files whose content is markup, such as HTML or
SVG: served from your own domain, such a file could run scripts in your
editors' sessions.

## Customize with site hooks

Four methods on the site change how the media library behaves. Add them to
your site subclass:

```python
# mysite/studio.py
from content_studio.admin import ContentStudioSite


class BlogStudioSite(ContentStudioSite):
    def get_thumbnail(self, obj):
        return obj.thumbnail.url if obj.thumbnail else obj.file.url

    def get_media_serializer_fields(self, media_model):
        return ["id", "name", "type", "tags", "file", "folder"]

    def crop_image(self, obj, crop_info):
        # Crop obj's file the way your project needs.
        ...


admin_site = BlogStudioSite()
```

- **`get_thumbnail(obj)`** returns the thumbnail URL of an image. By
  default, the file's own URL.
- **`get_media_serializer_fields(media_model)`** returns the fields of a
  media item the admin works with. By default, all fields; leave out fields
  editors should not see.
- **`crop_image(obj, crop_info)`** turns on cropping (see below).
- **`get_media_metadata(file, type)`** returns the [metadata](#metadata) to
  store for an uploaded file.

## Cropping and focal points

Cropping appears once the site defines `crop_image`. When an editor saves a
crop selection, the admin passes it to the method as percentages of the
image:

```python
{"x": "10.00", "y": "20.00", "width": "50.00", "height": "40.00", "unit": "%"}
```

What a crop does is up to your method: create a derivative, resize the file
in place or store the selection. The edit page then shows the updated item.

A focal point is one of the image's [properties](#properties): editors click
the image to set it. The [cover image widget](/docs/forms/widgets#cover-images)
sets the same focal point from the edit page.

## Metadata

The media library can store facts about each file, read once when the file
is uploaded or replaced: an image's width and height, or a video's duration.
The admin shows them in the file's details, and the
[cover image widget](/docs/forms/widgets#cover-images) uses an image's size
to warn about images that are too small.

1. Give your media item model a `JSONField` named `metadata`. The built-in
   `Media` model has one. To use a field by another name, name it in
   [`MEDIA_METADATA_ATTR`](/docs/settings#media_metadata_attr):

   ```python
   # blog/models.py
   from django.db import models


   class MediaItem(models.Model):
       class Type(models.TextChoices):
           IMAGE = "image", "Image"
           VIDEO = "video", "Video"
           AUDIO = "audio", "Audio"
           FILE = "file", "File"

       file = models.FileField(upload_to="media/")
       name = models.CharField(max_length=255, blank=True)
       type = models.CharField(max_length=10, choices=Type.choices, default=Type.FILE)
       metadata = models.JSONField(default=dict, blank=True, editable=False)

       def __str__(self):
           return self.name
   ```

2. Install Content Studio with the `images` extra, which adds
   [Pillow](https://python-pillow.org/) to read the size of images:

   ```bash
   pip install "django-content-studio[images]"
   ```

3. Read the metadata of the files you already have:

   ```bash
   python manage.py content_studio_media_metadata
   ```

   The command reads the items without metadata. Pass `--all` to read every
   item again, for example after you change what is read.

Images get `{"width": 1600, "height": 900}`, in pixels as the image is shown,
after its EXIF orientation. Other files get no metadata by default: a video's
duration and frame rate need a tool such as
[FFmpeg](https://ffmpeg.org/)'s `ffprobe`. Override `get_media_metadata` on
your site to read them. It receives the uploaded file and the item's type
(`"image"`, `"video"`, `"audio"` or `"file"`) and returns a dictionary of
JSON values:

```python
# mysite/studio.py
import json
import subprocess
import tempfile

from content_studio.admin import ContentStudioSite


class BlogStudioSite(ContentStudioSite):
    def get_media_metadata(self, file, type):
        if type != "video":
            return super().get_media_metadata(file, type)

        # ffprobe reads from a path: copy the upload to a temporary file.
        with tempfile.NamedTemporaryFile() as copy:
            file.seek(0)
            for chunk in file.chunks():
                copy.write(chunk)
            copy.flush()
            file.seek(0)

            result = subprocess.run(
                [
                    "ffprobe",
                    "-v",
                    "error",
                    "-select_streams",
                    "v:0",
                    "-show_entries",
                    "stream=width,height,r_frame_rate:format=duration",
                    "-of",
                    "json",
                    copy.name,
                ],
                capture_output=True,
                check=True,
                text=True,
            )

        probe = json.loads(result.stdout)
        stream = probe["streams"][0]
        frames, seconds = stream["r_frame_rate"].split("/")

        return {
            "width": stream["width"],
            "height": stream["height"],
            "duration": float(probe["format"]["duration"]),
            "frame_rate": round(int(frames) / int(seconds), 2),
        }


admin_site = BlogStudioSite()
```

The admin shows `width` and `height` in pixels, `duration` in seconds as
minutes and seconds, and `frame_rate` in frames per second. Other keys are
stored for your own templates and code. The method runs during the upload
request, so keep it fast; an exception in it fails the upload.

## Properties

Properties are values editors set for some types of media, stored in a
`JSONField` on the media item. The built-in `Media` model has a `properties`
field; give your own media model a `JSONField` named `properties`, or name
another one in [`MEDIA_PROPERTIES_ATTR`](/docs/settings#media_properties_attr):

```python
# blog/models.py
from django.db import models


class MediaItem(models.Model):
    class Type(models.TextChoices):
        IMAGE = "image", "Image"
        VIDEO = "video", "Video"
        AUDIO = "audio", "Audio"
        FILE = "file", "File"

    file = models.FileField(upload_to="media/")
    name = models.CharField(max_length=255, blank=True)
    type = models.CharField(max_length=10, choices=Type.choices, default=Type.FILE)
    properties = models.JSONField(default=dict, blank=True)

    def __str__(self):
        return self.name
```

The admin sets these properties:

- **`focal_point`**: the part of an image that stays in view when it is
  cropped, as `{"x": 0-100, "y": 0-100}`, percentages of the image's width
  and height from its top left. `None` when it is removed.

Unlike [metadata](#metadata), properties are kept when an item's file is
replaced. Other keys are kept as they are, so your own code can store values
there too. Read them in templates like any dictionary:

```django
{# blog/templates/blog/article_detail.html #}
{% with point=article.cover.properties.focal_point %}
  <img
    src="{{ article.cover.file.url }}"
    alt="{{ article.cover.alt_text }}"
    style="object-fit: cover; object-position: {{ point.x|default:50 }}% {{ point.y|default:50 }}%"
  >
{% endwith %}
```
