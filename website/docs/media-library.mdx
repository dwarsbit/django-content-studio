# 🖼️ Media library

The media library manages uploads in folders and lets fields reference them.
Point it at your own media and folder models:

```python
CONTENT_STUDIO = {
    "MEDIA_LIBRARY_MODEL": "myapp.models.MediaItem",
    "MEDIA_LIBRARY_FOLDER_MODEL": "myapp.models.MediaFolder",
}
```

With [Django Blueprint](/docs/blueprint-integration) installed, its media
library models plug in directly:

```python
CONTENT_STUDIO = {
    "MEDIA_LIBRARY_MODEL": "blueprint.media_library.models.Media",
    "MEDIA_LIBRARY_FOLDER_MODEL": "blueprint.media_library.models.Folder",
}
```

## Model contract

The interface works with any model, but it expects a handful of fields. Your
media model needs:

- a `file` field (the upload)
- a `name` — used by the library's search
- a `type` — `"image"`, `"video"`, `"audio"` or `"file"` drive the grid
  previews and thumbnails
- optionally `tags`, searched alongside the name — a list-typed field
  (a `JSONField` of strings, an `ArrayField`, or Blueprint's
  `TagField`); the tags input in the item editor works on the list
- optionally a `JSONField` for the focus point — set
  [`FOCUS_POINT_ATTR`](/docs/settings#focus_point_attr) to its name and the
  item editor offers a click-to-set focus point, stored as
  `{"x": 0-100, "y": 0-100}` (percentages of the image's dimensions)

Folder models need a self-referencing `parent` field; the rest (name,
children) follows from it. An unconfigured media library simply does not
appear in the interface. Missing contract fields are reported by the
`content_studio.W007` system check (see
[System checks](/docs/system-checks)).

## Managing media

The library is fully managed in the interface: upload files (with tags in the
same go when the model has a `tags` field), move them between folders and edit
their details — all against the models you configure. Image items can carry a
crop selection (see [cropping](#cropping)) and a focus point, applied on save.

Three views are offered through a toggle: the **grid** (thumbnails), a
**list** of rich rows and a **table** with sortable columns (name, type and
size — whatever the configured model carries). The view, the search, the
filters and the ordering all live in the URL, so filtered views are
deep-linkable and survive reloads and the back button.

The search box matches the name and the tags. Two filters narrow the items:

- the **type** — any of image, video, audio and file
- the **tags** — a searchable multi-select of the tags currently on
  the library's items, matching any of the selected tags

When folders are configured, the search either stays in the current folder
or searches across the whole library, through the toggle next to the
search box. Folders carry their item counts, and the header shows the
total.

Select items (a checkbox on every card, row or table line) to run bulk
actions: **delete** — with confirmation — and **move to folder**. The
actions run through one endpoint, permission-checked per action (delete
needs the model's delete permission, moving its change permission).

Files can also be uploaded by dragging them onto the library, with
per-file progress, and each item's context menu offers **Copy URL** and
**Download**.

## Hooks

- **`AdminSite.get_thumbnail(obj)`** — returns the thumbnail URL for an image
  item. The default returns `obj.file.url`; override to point at a
  pre-generated variant.
- **`AdminSite.get_media_serializer_fields(media_model)`** — controls which
  fields the serializer exposes. The default is `__all__`; override to keep
  sensitive custom fields out of the API.
- **`AdminSite.crop_image(obj, crop_info)`** — enables cropping. The base
  `AdminSite` does not define it; add the method to your site subclass and the
  item editor offers a crop selection for images. The crop info — the
  selection as percentages, `{"x": "10.00", "y": "20.00", "width": "50.00",
  "height": "40.00", "unit": "%"}` — is passed through verbatim when the item
  is saved; what cropping means (a derivative, an in-place resize, a stored
  preset) is up to the implementation.

```python
class CustomAdminSite(AdminSite):
    def get_thumbnail(self, obj):
        return obj.thumbnail.url if obj.thumbnail else obj.file.url

    def get_media_serializer_fields(self, media_model):
        return ["id", "name", "type", "tags", "file", "folder"]

    def crop_image(self, obj, crop_info):
        # Apply the crop to obj's file however your project sees fit.
        ...
```

## Cropping and focus points

A crop does not live on the media item: selecting one in the item editor sends
it to the site's `crop_image(obj, crop_info)` hook (see
[Hooks](#hooks)), which returns control to the editor with the updated item.
Without the hook, no crop UI appears.

The focus point, by contrast, is stored on the item: name its `JSONField` with
[`FOCUS_POINT_ATTR`](/docs/settings#focus_point_attr) and the editor offers a
click-to-set focus point saved with the rest of the item's details.
