# 🧩 Widgets

Every field renders with a widget. Widgets are chosen by field type through
the studio site's `default_widget_mapping`:

```python
from content_studio.admin import ContentStudioSite
from content_studio import widgets


class MyStudioSite(ContentStudioSite):
    default_widget_mapping = {
        **ContentStudioSite.default_widget_mapping,
        models.EmailField: widgets.InputWidget,
    }
```

## Default mapping

| Field type | Widget |
|-----------|--------|
| `CharField` and numeric fields | `InputWidget` |
| `SlugField` | `SlugWidget` |
| `TextField` | `TextAreaWidget` |
| `BooleanField` | `CheckboxWidget` |
| `ForeignKey` / `OneToOneField` | `ForeignKeyWidget` |
| `ManyToManyField` | `ManyToManyWidget` |
| `DateField` / `DateTimeField` / `TimeField` | Dedicated date/time widgets |
| `JSONField` | `JSONWidget` |
| `HTMLField` (built-in) | `RichTextWidget` |
| `TagField`, `FlexField`, `MultipleChoiceField`, `URLPathField` (built-in) | Dedicated widgets |
| `MediaField` / `ManyMediaField` (built-in) | Media picker widgets |
| `"AutoSlugField"` (string key) | `SlugWidget` |

Unknown field types fall back to a plain input; unknown widget names fall
back to a read-only display. Choice fields render as selects automatically.
Two widgets outside the default mapping are available for overrides:
a `SwitchWidget` for `BooleanField`s better presented as a toggle, and a
`ToggleGroupWidget` for choice fields better presented as a group of
toggles — exactly one active at a time, and a required field cannot be
left without one.

## Per-field override

The mapping is a default, not a verdict: pass a widget class to a `Field` in
`edit_main` or `edit_sidebar` to render that one field differently.

```python
from content_studio.form import Field, FormSet
from content_studio import widgets


@register(Article)
class ArticleStudio(ModelStudio):
    edit_main = [
        FormSet(
            fields=[
                Field("summary", widget=widgets.TextAreaWidget),
            ],
        ),
    ]
```

The override applies to the editing widget only; read-only fields keep
formatting their value through the format mapping.

## Custom widgets

The widget classes are markers: the interface ships a renderer for each
built-in widget, and a widget is identified by its class name. Version 1
supports the built-in widgets and formats only — map fields to any of
them, but subclassing `BaseWidget` or `BaseFormat` has no renderer to pair
with. Custom widgets and formats are planned for a later release, together
with a way to extend the interface.

## Formats

List values are formatted through the site's parallel
`default_format_mapping`: dates, times, booleans, numbers, tags, HTML and
media references each have a formatter, and the mapping is customized on
the `ContentStudioSite` in the same way as widgets.
