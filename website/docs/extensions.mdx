# 🔌 Extensions

Extensions add links, buttons and pages to the admin's menus: a link to an
external tool, a button that runs your code, another web application shown
inside the admin, or a page with a dashboard of its own. For your website's
visitor statistics, see [Analytics](/docs/analytics).

```python
# mysite/studio.py
from content_studio.admin import ContentStudioSite
from content_studio.extensions import IFramePage, MainMenuLink


class BlogStudioSite(ContentStudioSite):
    extensions = [
        MainMenuLink(
            url="https://status.example.com",
            label="Status",
            icon="ph-bold ph-heartbeat",
        ),
        IFramePage(
            path="reports/",
            iframe_url="https://metabase.example.com/dashboard/1",
        ),
    ]


admin_site = BlogStudioSite()
```

## MainMenuLink

A link in the admin's main menu. It takes a `url`, a `label` and an `icon`,
and optionally a `color` and a `weight`. The `url` is a page of the admin,
such as `"/reports/"` for an `IFramePage`, or an `http(s)` URL, which opens in
a new tab. The menu orders its links and buttons by `weight`, lowest first;
with equal weights, which is the default of `0`, they keep their order in
`extensions`.

To show a link to some users only, subclass it and override
`is_visible(request)`:

```python
class ReportsLink(MainMenuLink):
    def is_visible(self, request):
        return request.user.is_superuser
```

## MainMenuButton

A button in the admin's main menu that runs your code on the server, such as
clearing a cache or starting a deployment. Subclass `MainMenuButton` and
implement `handle(request)`:

```python
# mysite/studio.py
from django.core.cache import cache

from content_studio.admin import ContentStudioSite
from content_studio.extensions import MainMenuButton


class ClearCacheButton(MainMenuButton):
    label = "Clear cache"
    icon = "ph-bold ph-broom"
    confirm = "Clear the cache for every visitor?"

    def is_visible(self, request):
        return request.user.is_superuser

    def handle(self, request):
        cache.clear()
        return "The cache is cleared."


class BlogStudioSite(ContentStudioSite):
    extensions = [ClearCacheButton()]


admin_site = BlogStudioSite()
```

- `label`, `icon`, `color` and `weight`: as for `MainMenuLink`.
- `confirm`: a question to confirm before the button runs.
- `is_visible(request)`: who sees the button. By default every staff user
  does. Content Studio checks it again when the button runs.

`handle` returns what the editor sees: a string as a notification, or a
[`ButtonResult`](/docs/edit-page#buttons) with a `message` and a
`value` that appears once in a dialog with a copy button. The options can
also be passed as arguments, such as `ClearCacheButton(label="Empty
cache")`. Record the changes the button makes with `record_change`, so they
appear in the objects' history. The [webhooks app](/docs/webhooks#a-deploy-button-and-a-dashboard-widget)
ships one ready to use: `DeployButton`.

## UserMenuLink and UserMenuButton

A link or a button in the user menu, the menu under the user's name, between
the theme and logging out. They take the same options as `MainMenuLink` and
`MainMenuButton`, including `is_visible(request)`, and the user menu orders
them by `weight` the same way:

```python
# mysite/studio.py
from content_studio.admin import ContentStudioSite
from content_studio.extensions import UserMenuLink


class TaskQueueLink(UserMenuLink):
    def is_visible(self, request):
        return request.user.is_superuser


class BlogStudioSite(ContentStudioSite):
    extensions = [
        UserMenuLink(
            url="https://help.example.com",
            label="Help",
            icon="ph-bold ph-question",
        ),
        TaskQueueLink(url="/tasks/", label="Task queue", icon="ph-bold ph-queue"),
    ]


admin_site = BlogStudioSite()
```

## IFramePage

A page in the admin that shows another web page in an iframe. `path` is the
page's address under the admin's URL prefix, `iframe_url` the page it shows.

The embedded page runs in a sandbox: it can run scripts, keep its origin,
submit forms, open windows and offer downloads, but it cannot navigate the
admin away, show modal dialogs or lock the pointer. The `sandbox` option
takes another string of
[sandbox tokens](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)
to tighten or widen it, or `None` to embed the page without a sandbox:

```python
IFramePage(
    path="reports/",
    iframe_url="https://metabase.example.com/dashboard/1",
    sandbox="allow-scripts allow-same-origin",
)
```

You choose the page the iframe shows, so the admin trusts it to that extent:
a page that may navigate the admin or open dialogs needs `sandbox=None`.

## DashboardPage

A page in the admin with a [dashboard](/docs/dashboard) of its own, such as a
screen of task queue statistics next to the start page. `path` is the page's
address under the admin's URL prefix, `title` its heading and `dashboard` a
`Dashboard` with its widgets. An optional `description` shows under the
title. Link to the page with a menu link to its path.

```python
# mysite/studio.py
from content_studio.admin import ContentStudioSite
from content_studio.dashboard import Dashboard
from content_studio.extensions import DashboardPage

from blog.dashboard import LatestArticlesWidget, PublishedArticlesWidget


class ReportsPage(DashboardPage):
    def is_visible(self, request):
        return request.user.is_superuser


class BlogStudioSite(ContentStudioSite):
    extensions = [
        ReportsPage(
            path="reports/",
            title="Reports",
            description="How the blog is doing.",
            dashboard=Dashboard(
                widgets=[PublishedArticlesWidget(), LatestArticlesWidget()]
            ),
        ),
    ]


admin_site = BlogStudioSite()
```

`is_visible(request)` decides who sees the page. By default every staff user
does. Content Studio checks it again whenever one of the page's widgets loads
its data, so the widgets of a hidden page show nothing.

The page's widgets work as on the start page. Their IDs must be unique
across the start page and every dashboard page; system check
`content_studio.E004` reports duplicates. A path that one of the admin's own
pages uses, such as `content/` or `media-library/`, is reported by system
check `content_studio.E028`.

## Two identical extensions

Two extensions with the same settings need an explicit `extension_id` (a
UUID) to tell them apart; `manage.py check` reports duplicates.
