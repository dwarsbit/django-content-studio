# 🛡️ Access control

Content Studio reuses the Django admin's permission system. A user needs
Django's model permissions to see and change content in the studio, and the
familiar `ModelAdmin` hooks can restrict access further — per object.

## Model-level permissions

Access is checked against the model admin's permission methods, which
default to Django's model permissions:

| Method | Default behavior |
|--------|------------------|
| `has_view_permission(request)` | Django's `view` permission |
| `has_add_permission(request)` | Django's `add` permission |
| `has_change_permission(request)` | Django's `change` permission |
| `has_delete_permission(request)` | Django's `delete` permission |

A staff user needs the matching Django permission on the model — superusers
have them all. Grant them like anywhere else in Django, through groups or
user permissions.

## Object-level permissions

The per-object variants are honored throughout the interface — a user only
sees and edits the objects you allow:

```python
@register(Article)
class ArticleAdmin(ModelAdmin):
    def has_view_permission(self, request, obj=None):
        if obj is None:
            return super().has_view_permission(request)
        # Editors only see their own articles:
        return obj.author_id == request.user.id or request.user.is_superuser
```

By default the object-level variants fall back to the model-level check, so
behavior out of the box matches the classic admin. The same hooks protect
everything around the objects too: related model options are only offered
when the user may view the related model, and inline objects can only be
attached to parents the user can see.

## Login throttling

Login attempts are rate limited per IP; the default is 10 per minute. Change
or disable it with the `LOGIN_THROTTLE_RATE` setting:

```python
CONTENT_STUDIO = {
    "LOGIN_THROTTLE_RATE": "5/min",  # or None to disable
}
```

:::note
The limit is enforced through the cache. With the default per-process cache
every worker counts separately — configure a shared cache (Redis, Memcached)
for the full limit in multi-worker deployments.
:::

## What is deliberately not included

- **Session invalidation after a password reset.** JWT access tokens remain
  valid until they expire. Token blacklisting is planned for the auth
  hardening release.
- **Field-level permissions.** The editor exposes the model's fields;
  restrict with a custom serializer or keep sensitive data out of admin
  models.
