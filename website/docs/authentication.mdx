# 🔐 Authentication

Content Studio ships with JSON Web Token authentication
([djangorestframework-simplejwt](https://django-rest-framework-simplejwt.readthedocs.io/))
and a pluggable login backend system.

## Login backends

A login backend is a small class with a name, a DRF view set and the login
logic. The default username/password backend posts to
`api/login/usernamepassword`:

```
POST /api/login/usernamepassword
{"username": "admin", "password": "..."}
→ {"refresh": "...", "access": "..."}
```

Access tokens authorize every API call; expired access tokens are refreshed
through `api/tokens/simplejwt/refresh`. Configure additional backends —
SSO, magic links, LDAP — with the `LOGIN_BACKENDS` setting; the frontend
renders a form per backend automatically. Each backend gets its own route,
and login attempts are throttled per IP
([`LOGIN_THROTTLE_RATE`](/docs/settings#login_throttle_rate)).

```python
CONTENT_STUDIO = {
    "LOGIN_BACKENDS": [
        "content_studio.login_backends.UsernamePasswordBackend",
        "myapp.login.MagicLinkBackend",
    ],
}
```

The backend interface:

```python
class MagicLinkBackend:
    name = "Magic link"
    view_set = MagicLinkViewSet  # a DRF ViewSet with a `create` action

    @classmethod
    def get_info(cls):
        # Sent to the frontend so it can render the right form.
        return {"type": cls.__name__, "config": {}}

    @classmethod
    def get_response_for_user(cls, user):
        # Build the authentication response — the JWT backend returns
        # {"refresh": ..., "access": ...}.
        ...
```

## Token backend

Tokens themselves come from the token backend (`SimpleJwtBackend` by
default), which exposes simplejwt's authentication class, the refresh endpoint
and the response format. Custom token backends follow the same small
interface.

## Password reset

The `content_studio.contrib.password_reset` app adds the classic email code
flow:

```python
INSTALLED_APPS = [
    # ...
    "content_studio.contrib.password_reset",
]

urlpatterns = [
    path("admin/", include("content_studio.contrib.password_reset.urls")),
    # ...
]
```

```
POST /admin/api/password-reset/request   {"email": ...}  → 202 always
POST /admin/api/password-reset/code      {"email", "code"} → 204
POST /admin/api/password-reset/submit   {"email", "code", "password"} → 204
```

Codes are six digits, generated with `secrets`, valid for 10 minutes (the
[`PASSWORD_RESET_EXPIRATION_TIME`](/docs/settings#password_reset_expiration_time)
setting) and invalidated after five failed attempts. Validation is bound to
the email: unknown emails and wrong codes answer identically, so the
endpoints do not reveal which addresses exist.

Configure `EMAIL_*` settings — Content Studio sends the code email with
`send_mail`.
